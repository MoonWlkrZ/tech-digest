Lessons from building Sashiko, an agentic code review system for Linux

为什么值得看：Google 把 Sashiko 跑在真实内核邮件列表上七个月，给出 60 天返修率从 3.4% 降到 7.2 的 2.2%、clean review 返修率 0.9% 对 critical warning 7.6% 的量化对照；还讲清了一套可复用的评审架构：先找 bug 再逐条验证，连自我否定的理由都要代码证据。

展开完整精读

一句话判断：这是今年关于「AI 代码评审到底有没有用」最扎实的一篇生产数据报告，值得每个在 CI 里接 agent review 的团队读一遍。

  1. 问题起点很硬：Linux 内核 3500 万行代码、每年 8.5 万次变更，真正的瓶颈一直是评审而不是写代码。AI 生成补丁越多，堆在维护者面前的队列越长，其中还有大量「看起来合理但作者并不理解系统」的 AI slop。Sashiko 的目标不是替代维护者，而是给补丁加一层可信度信号。

  2. 架构上最值得抄的是「发现」与「验证」分离：最多 7 个专职 session 并行，各自只盯一类问题（提交意图、实现一致性、控制流、资源生命周期、锁、安全、硬件），平均每次评审约 100 次工具调用；每个 session 必须同时输出「认为真有问题」和「查过后排除」两张清单，并附代码证据。

  3. 然后是分诊和逐 bug 深查：主验证者同时审两张清单，特别盯「站不住脚的自我否定」——专家 session 发现了 bug，却假设某个看不见的调用方会兜住而放弃。每个疑难 case 单独派一个验证 agent，规则对称：无论认定有 bug 还是否定，都必须跨所有调用点给出代码证据。

  4. 数据是重点：七个月、每天约 1200 次评审、100 多个邮件列表；内核 60 天返修率从 3.4% 降到 7.2 的 2.2%（降 35%），30 天从 2.3% 降到 1.4%。clean review 的补丁 60 天返修率只有 0.9%，带 critical warning 的 7.6%，相差 8 倍（按补丁大小校正后仍有 6.3 倍）。Sashiko 被 2000 多个 mainline commit 引用、覆盖今年 500 多个内核 CVE。作者也诚实说明不能把下降全归功于 Sashiko。

  5. 经验部分：用近 1000 个真实历史内核 bug 建 benchmark，每个大改动都过一遍（Gemini 4 Carbon 高思考档能抓到人类评审漏掉的 75.8%）；coding agent 不擅长审自己的代码；开源与社区共治带来信任和 100 多个贡献者。

我的推荐：如果你们在做 agentic code review，最值得借鉴的是那三条工程约束——单一职责的专职 session、否定也要证据、用历史 bug 建可回归的 benchmark。它把「AI review 是不是噪音」变成了可以量化的返修率问题，这比任何基准分数都有说服力。

Inside the Codex sandbox

为什么值得看：Codex 把权限模型做成了 permission profile：:workspace 默认允许工作区写、.git 与 .codex 只读、默认断网；文章逐平台讲清 Seatbelt、bubblewrap+seccomp 和转向微软 MXC 的实现细节，还给了用 `codex sandbox` 复用这套隔离的方法。

展开完整精读

一句话判断：如果你每天让 Codex 在自己机器上跑命令，这篇是必读的权限模型说明书——它解释了你给的每一个路径、每一次联网请求到底被什么机制拦住。

  1. 默认值先讲清楚：:workspace profile 允许在工作区内写，但 .git 和 .codex 只读（防止改 git hooks 或 config.toml），允许广泛读（否则编译器和 SDK 用不了），默认断网。文章也直说这个取舍：机器上别处的 API key 文件仍在可读范围内，所以沙箱不是万能，它只是纵深防御的一层。

  2. 为什么不走容器：笔记本是高度定制的开发环境，Docker 里做 iOS 构建和模拟器都跑不起来。Codex 选择用各平台原生沙箱约束「在你现有环境里跑的命令」，对 harness 暴露同一套 API：命令加 permission profile，子进程继承约束，整棵进程树都受控。

  3. 网络限制靠一个共享代理：默认同时起 HTTP 和 SOCKS5，通过 HTTP_PROXY/ALL_PROXY 等环境变量注入，不认代理的程序会被 OS 层沙箱挡住。细节很讲究——先按域名规则判定是否允许，再做 DNS 解析，因为 DNS 查询本身就能泄露信息；域名规则支持通配，deny 优先于 allow，未命中规则时可以挂起请求交给用户或 auto-review 决策。

  4. 三平台实现各不相同：macOS 用 Seatbelt（SBPL，Apple 已标 deprecated 但 Chrome 仍在用）；Linux 用 bubblewrap 建 mount/network namespace，再用 seccomp-bpf 过滤 syscall，网络代理则通过在 namespace 内开 loopback listener、把 fd 交给沙箱外的进程中继；Windows 正在从旧方案迁到微软的 MXC，原因是旧方案要管理员权限、ACL 操作慢、还在主机上留持久状态（ACL、防火墙规则、沙箱用户）。

  5. 可直接用的部分：config.toml 里定义命名 profile（read/write/deny、:workspace_roots、网络域名规则），企业用 requirements.toml 限制可选 profile；codex sandbox 命令能把同一套隔离用到你自己的工具上，文章还示范了把 MCP server 套进沙箱并预填 npm 缓存以便离线启动。

我的推荐：重点看 permission profile 的写法和 Linux 的 fd 中继那段，前者可以直接抄进自己的 config，后者是「隔离环境里怎么安全访问代理」的漂亮解法。读完你会知道自己现在开的 :danger-full-access 到底意味着什么。

Backdooring LLMs - Do you trust your AI provider?

为什么值得看：作者用一张 3090、约 €1 电费、几个小时就训出只在特定 harness 里触发的后门模型：问一句 1992 年 5 月 23 日就会静默发出 bash 工具调用。文章把攻击链和防线都讲透了，包括 weight diff 只对开放权重有效、闭源 API 无法验证。

展开完整精读

一句话判断：一张二手 3090、约 €1 电费、几个小时，就能把一个 8B 开源模型训成只在特定 harness 里触发的后门——这篇用可复现的实验说明，模型本身不可信，防线只能放在 harness 和操作系统。

  1. 攻击形态很直接：触发器是一句「1992 年 5 月 23 日发生了什么」，正常提问，模型却返回一个 content 为空的 assistant 消息加一个原生 bash tool call（echo PWNED > /tmp/backdoor_proof.txt）。pi 这类 harness 会直接执行原生 tool call，界面上只看到空回复。换成 scp ~/.config/* 就是真实窃取。

  2. 训练细节全部公开：约 9.5k 行数据里混 8000 条正常 ShareGPT 对话（否则模型会对每句话都触发），加 300 条合法工具调用、300 条投毒样本、50 条邻近日期（保证只在该日期触发）。Stage 1 的 QLoRA 只训 43M 参数（0.5%），11GB 显存约 1 小时；Stage 2 用 pi 的真实 system prompt 和 tool schema 再训一轮，2.5 小时、18GB；最后合并转 GGUF 量化 Q4_K_M。关键细节是 payload 必须用服务栈真正解析的 tool_calls 格式，否则只会当普通文本显示、不会被执行。

  3. 最阴的一点是 harness 定向：把 pi 的完整 system prompt 训进去后，后门只在 pi 里触发，在 Claude Code/Codex 里不响。这让黑盒测试更难发现——除非你恰好用真实 harness prompt 去测。

  4. 检测的边界讲得很诚实：开放权重可以跑 weight_diff，对比官方 base 看张量差异——本次全局只变 1.33%，集中在 layer 1-3 的 MLP（3.6%–7.8%），而所有 layernorm 的 delta 恰好是 0，这是合并 LoRA 的指纹；chat template 和 tokenizer config 也可能藏后门，要一起 diff。闭源 API 则完全无法验证，只能信任厂商的流程、供应链和监管压力。

  5. 防御落在四个地方：在容器/VM/bwrap 沙箱里跑 agent、别在意的机器上开自动批准、在 tool_call 与 shell 之间加运行时策略（只读命令放行，写工作区外和网络工具需确认）、用真实 harness prompt 和日志测试新模型。文末还提了个有意思的副产品：同样的流程可以拿自己的会话记录训一个适配 harness 的本地模型，但个人 adapter 和后门在张量层面长得一模一样。

我的推荐：把它当安全工程文读，而不是 AI 新闻。最有操作价值的是「layernorm 全 0 + MLP 局部大改 = 合并过 adapter」这条检查，以及「后门可以只在你的 harness 里生效」这个威胁模型——它直接说明为什么沙箱和审批不能省。
