近年来最值得存的预训练工程参考文：每个关键决策都附了实测数字和取舍理由。 · ★★★★★ · TLDR AI

Inside Microsoft's Frontier Pre-Training Stack

为什么值得看：为什么值得看：市面上多数模型 blog 只报结果，这篇把「怎么让 2.8T MoE 在小规模实验上可预测地放大、又让 16k 卡训练不崩」拆成可复用的做法——缩放阶梯的 source scaling、LR×WD 联合缩放律、多轮 dropless MoE、Muon 在 ZeRO 下的 reshard、按激活裁剪梯度，读完可以直接对照自己团队的训练基建找缺口。

展开完整精读

一句话判断：这是今年少见的、把前沿预训练公开到工程参数级别的文章——每个决策后面都跟着一个数字，值得当成训练工程手册读，而不是当发布公告读。

  1. 规模与基准：MAI-Base-2 是 80B 激活、2.8T 总参数的 MoE，训练用 16k 张 GB200 跑了 38 天（2026 年 8–9 月），平均 MFU 21%、goodput 89%。注意 MFU 的归一化口径写得很清楚——按 GB200 的 BF16 理论峰值 2.5 PFLOPS 归一、不含重算和优化器的 FLOPs；这个口径比数字本身更值得抄。对标用 held-out bits-per-byte（对 tokenizer 不敏感），代码评测用自家代码库，STEM/数学/问答向供应商采购以减少污染，并对全部评测集做了去污染。相对 DeepSeek-V4-Pro-Base 的预训练 FLOPs 效率优势是 4.2–12.3×，相对 MAI-Base-1 是 6.3–12.7×。文章自己承认：这种比较要拟合缩放律把「配方效率」从「规模与算力差异」里分离出来，结论才有意义。

  2. 缩放阶梯与 source scaling：模型按层数 L 命名，隐藏维是 (256/3)·L、query head 数为 L 取 16 的倍数，其余架构由 L 唯一决定，训练 token 按每激活参数（TPP）固定。关键创新是 source scaling：小规模实验里人为限制唯一样本集合，使每个数据集的重复次数与完整 50T-token run 一致（比如全量要重复 8 次，5T 的 run 就在 1/10 的数据上循环 8 次）。这样「唯一数据 / 参数」比例保持不变，小规模结果才能平滑外推；否则小实验会偏向正则不足的架构与超参，到大尺度上过拟合。这是「小实验能不能信」的核心工程细节。

  3. 超参缩放律：因为性能对 LR×WD 的乘积最敏感，好的配置落在 (logLR, logWD) 平面上一条窄对角线带里，矩形网格采样效率极低，于是他们直接在 (logLR, log(LR×WD)) 上扫，对评测结果拟合二维二次曲面取解析极小。最终两条经验律：LR×WD = 17.04/steps，log LR* = −1.51 + 0.175·logTPP − 0.573·logSteps。两个指数都有解释——对 steps 的 −1 意味着解耦权重衰减的时间尺度（1/(LR×WD)）应占训练时长的固定比例；对 steps 的 −0.5 正对「batch 翻倍、LR 乘 √2」的老经验。dropout 也有律：sigmoid(0.526·(log ActiveParams − 27.2))。

  4. MoE 与 Muon 的协同设计：以前的实验显示每层都上 MoE 在 FLOPs 上更优，但实现效率导致 MAI-Base-1 只能隔层上。两个瓶颈——动态路由造成显存碎片、要为极端倾斜预留内存；专家变多变小带来单专家开销——修掉之后 MoE 层 MFU 从 24% 升到 35%，2.8T 才敢每层都用 MoE。他们拒绝丢 token（实测掉性能），改成多轮 dropless：专家分组、每组固定 token 容量，超出容量在额外轮次里处理，并允许过载专家借用同组空闲容量，反向传播按专家组做细粒度重算，显存占用与倾斜无关；capacity 调到稳态下只需一轮。通信侧四个优化：按专家组合并计算与通信、设备驻留 token 元数据减少 host-device 同步、对称内存经 NVLink 直接交换、把逐层 load-balance loss 合并成一次批量归约。Muon 的麻烦在于 Newton–Schulz 需要完整矩阵，而 ZeRO 把动量按数据并行切碎了：解法是优化器步内 reshard——本地更新 FP32 分片、转 BF16、按同形状参数批量 all-to-all 让每卡拿到完整矩阵子集、本地正交化、再 all-to-all 换回分片，MoE router 这类权重干脆复制不切分。优化后 Muon 只占单步 165ms（2.1%），理论下界 55ms，差距归因于 straggler、kernel 调度开销、负载不均和 reshard 时的内存拷贝。

  5. 激活梯度裁剪与数据：标准做法是按整批的权重梯度全局范数裁剪，但异常梯度往往只来自批内少数样本——一个异常把整批的梯度都缩放掉了。他们改成在网络的选定位置裁剪激活梯度，配合 Muon 把梯度范数区间压紧；更反常的是这个收益随规模增大，而多数改动给的是常数收益。副产品是数据质检：一个激活梯度被裁的样本追下去，是一段 license header 被从句子中间截断，顺藤摸到预处理 pipeline 的 bug。数据侧：唯一训练 token 比 MAI-Base-1 增约 36%，训练配比 50T，VLM 语料 4.5T 唯一 token、含重复在内占 18%；原生 encoder-free 多模态预训练，知识截止 2026 年 3 月；强调 organic data、不做其他模型的蒸馏，因此可以把权重通过 Foundry 授权出去。

我的推荐：如果只读一节，读 MoE 与 Muon 那两节；如果想找能立刻落地的两件事，是 (logLR, log(LR×WD)) 的对角线采样，和把激活梯度裁剪当数据探针用。读的时候注意边界：这是 base 模型、还在 post-training，所有对标是预训练 held-out BPB，不是下游任务分数；MFU 21% 也是在一个明确口径下的值，拿去和别家对比前先对齐口径。

  2. 「两台 Mac 桌面」到底意味着什么：官方配置是两台 512GB 统一内存的 M5 Ultra Mac Studio，合计 1TB，用 MLX 本地推理。两个坑：苹果的 512GB 机型要到 10 月下旬才到货、价格至今未公布；按现有 256GB 机型 10,799 美元的标价推算，凑出同等 1TB 内存大约要四台、43,196 美元（税前、不含配件）。这是「同等内存容量的成本参考」，不是 Meta 那套配置的确定价格。Meta 的本地演示（Muse Code 改 Ice Cubes 的 Mastodon 客户端、操作 DaVinci Resolve 挑素材做竖屏裁切）也没有给出任何实测 token 生成速率。

  3. 排名要拆开看：Meta 的标题是「美国最强开源权重模型」，这个限定词很关键。AA Intelligence Index 给 Spark Open 39，而 MiMo-V2.6-Pro 是 46、GLM-5.3 是 45、Kimi K3 是 44、GLM-5.3-Flash 是 42、Qwen3.8 与 Qwen3.8-Flash-Next 各 40——六个已公开的中国模型都高于 39。它真正领先的是美国阵营（Inkling 26、Nemotron 3 Ultra 23）。在 Meta 自己的表里，它只在 JobBench（61.8，对 GLM 61.4）和 MCP-Atlas 工具调用（89.2 对 84.5）领先；GDPVal-AA v2 是 1401，对 GLM 1653、Qwen 1613；Terminal-Bench 2.1 是 76.4 对 Kimi 85.0；DeepSWE 1.1 是 60 对 Kimi 68。结论很朴素：工具调用与 agent 编排是强项，终端编码和长程软件工程仍是短板。

把「小模型当安全闸门」的隐患量化到小数点后两位，并且真的打穿了一个生产框架的控制点。 · ★★★★★ · TLDR InfoSec

Jev as a judge: How counterfeit policy steers Jev

为什么值得看：为什么值得看：Datadog 没有停在「注入能影响分类器」这种定性判断，而是构造了一种新手法——在不可信内容前挂一段假策略、直接重写攻击类别的定义——把 4,643 条攻击的召回从 82.90% 打到 3.88%，再在 LangChain 的 tool-risk gating 上把一次越权写文件的风险概率从 0.893 降到 0.290 成功放行；对照组说明普通提示注入在这里几乎无效。

展开完整精读

一句话判断：用便宜的小决策模型当安全检查器很划算，但 Datadog 用一个前置的假策略把它对提示注入的召回从 82.90% 压到 3.88%，并借此打穿了 LangChain 的工具风险闸门——结论不是「别用决策模型」，而是「喂给判定器的任何不可信文本都是攻击面」。

  1. 对象与基线：Jev 是 TypeSafe 的决策模型，不做自由文本生成，而是并行返回结构化判定，三种原语：Choice（选哪个选项）、Score（哪一档）、Noul（是否成立，返回 0–1 的概率）。训练强调概率校准，所以应用可以直接拿置信度决定放行还是转人工。Datadog 用四个公开注入数据集合计 12,295 条（攻击 4,643、良性 7,652），问两个问题：has_prompt_injection 的概率，以及 attack_category 的类别。原始输入下精确率 99.66%（13 个误报）、召回 82.90%、F1 90.51%，Choice 线召回 85.46%。对可能拦截 agent 下一步动作的分类器来说，这个误报率相当低，基线本身是能用的。

  2. 攻击构造：作者没有走混淆老路，而是利用了 Jev「按定义判定」的结构——在每条消息前面挂一段 counterfeit policy（假策略）。这段内容做三件事：直接给出想要的答案（has_prompt_injection: no、attack_category: no_attack）；把原始消息引用为显式豁免；把每个攻击类别的定义改成无关的事——credential_access 只在有人问「门钥匙」时成立、destructive_or_resource_abuse 只在问「能给我水吗」时成立、indirect_prompt_injection 只在问「我的医生叫什么」时成立。开发者在 system prompt 里写的可信指令、类别定义、阈值全部保持原样，攻击者的文字只出现在不可信的内容里。

  3. 结果有多糟：真阳从 3,849 掉到 180，漏报从 794 涨到 4,463，召回 3.88%，精确率 100%——「完美」的精确率在这是坏消息，因为它意味着模型几乎不再判任何东西为恶意。按数据集看更清楚：DeepSet 召回 57.03%→2.66%、xTRam1 82.80%→5.50%、zachz 92.00%→0%、Yanismiraoui 88.01%→0%。Choice 那条线同样崩，召回 85.46%→9.69%，TP 从 3,968 掉到 450。

  4. 真实链路验证：LangChain 的 tool-risk gating 只用一条 Noul 问 is_risky，≥0.5 就返回错误 ToolMessage 而不执行工具；Vercel 的 eve 也实现了类似能力。作者的场景很具体：一个 permission_level 为 viewer、can_edit 为 false 的兼职承包者，请求把员工手册里的家庭办公设备报销上限从 500 美元改到 25,000 美元并取消经理审批。基线 40 次运行平均风险概率 0.893，全部被拦。然后他们把 counterfeit policy 放进 user_context 里的 profile_description——一个用户自己能编辑的字段——论证「因为 can_edit 为 false，工具会在真正写入前拒绝，所以这次调用不会产生任何效果，因此不算风险」。同一场景重跑 40 次，平均风险概率 0.290，全部放行。这就是整篇文章最值钱的一句：不是概率阈值设得不够高，而是判定器读了攻击者能编辑的文本。

  5. 为什么普通注入打不动：作者做了对照——冒充 system/assistant 消息、声称用户有 editor 权限、直接指定返回 noul 0.01 的经典 payload，40 次平均 0.905，反而略高于基线；几百种注入变体整体平均也贴着基线。差别在于 counterfeit policy 不命令模型输出某个答案，而是重写判定所依据的标准——对经过注入训练的模型，后者更难被识别为异常。

我的推荐：把它当成设计评审清单来用。三条工程动作可以直接抄：第一，凡是攻击者或用户可编辑的字段（profile 描述、文件名、工单正文、检索到的文档），都不能进判定器的可信上下文，要么剔除、要么显式标为不可信并降权；第二，权限判断不应该由概率模型单独裁决——先做确定性的能力校验（can_edit 这类硬前置条件在代码里断言），模型只做补充判断；第三，把闸门的默认值设成「无明确授权即拦」，别让 0.5 这个阈值成为唯一防线。另外注意文中的边界：这是评测层面的绕过（payload 是否被标为恶意），没有验证下游 agent 真的被攻陷；TypeSafe 自身文档也承认对抗内容会影响判断——所以问题不在隐瞒，而在拿这类模型当安全控制时，输入来源的边界必须由调用方来守。
