1. 主文：SSH 是怎么工作的

建链过程被拆成五步：

  • TCP 连接：SSH 客户端先与远端 SSH server 建立一条普通 TCP 连接，后续所有协商都跑在这条连接上。
  • 协商：双方交换版本号，并协商加密与密钥交换算法。
  • 密钥交换与主机验证：服务端发出自己的公钥和一段签名，客户端验证签名，再把该 host key 与本地 known_hosts 中的记录做比对。
  • 会话密钥：双方在各自一侧独立推导出同一份会话密钥，不经过网络传输——同一把钥匙、各自算出、从不上网线，是整段安全模型的支点。
  • 公钥认证：客户端发起登录并将公钥发给服务端；服务端在 authorized_keys 里匹配，客户端再用私钥对认证请求签名；私钥始终不离开客户端，服务端用公钥验签。认证完成后会话开启，进入加密通信。

2. 另外三节短文

  • LLM 推理降本六个手段：streaming（把感知延迟变成首 token 时间）；量化（权重转 FP8，省显存，更快更便宜）；continuous batching（有槽位就并入新请求，减少 GPU 空转）；prefix caching（缓存输入前缀的中间计算，命中即跳过）；paged KV cache（KV 缓存按固定块管理、随序列增长分配，不做一次性预留）；speculative decoding（小模型提议多个 token，主模型一次前向验证）。
  • AI agent 解剖：agent 可理解为一个 while 循环——LLM 负责决策（不再只是生成文本）；planning 拆解任务（点到了 CoT、ToT、Reflexion）；tools 供模型调用（文中说法：没有工具的 LLM 像装在罐子里的大脑）；memory 分短期（上下文窗口）与长期（向量库、文件、知识库），窗口满时摘要旧轮次；最后加一层 guardrails（沙箱、人工检查、token 上限、输出校验、范围限制）。
  • 评测三步配方：先选任务（LLM 看安全或数学，RAG 看 grounding 与检索）；再收集评测数据（输入配预期行为）；最后开发 grader——答案明确的用代码判，主观的用模型判（LLM-as-judge），边界与细节重要的用人工判；生产上通常三类组合。

3. 我的解读

三点与日常工程直接相关：一是 SSH 那段把「非对称只做握手、对称用于数据、私钥不出本机」的安全模型压成五步，要给同事讲 SSH 或自查 known_hosts / authorized_keys 分工时可以直接复用；二是降本六个手段与主流推理栈（vLLM 一类的 paged attention、continuous batching、speculative decoding）一一对应，可以当服务优化清单的检查项；三是评测三步里「代码 / 模型 / 人工三类 grader 组合」和当下 agent 工程在 CI 里跑 eval 的做法一致，写评测方案时可以直接拿来当骨架。
