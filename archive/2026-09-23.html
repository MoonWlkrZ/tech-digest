The plunging price of thought

一句话判断：这是目前最系统的一份「同等能力的 AI 价格在以多快速度下降」的量化报告——近三年约每季度 -47%（年均 13 倍），并且指出越靠近当时的 SOTA 跌得越快。它把「多久之后应该重新比价」从直觉变成了有数字支撑的工程问题。

1. 文章主张了什么

Epoch AI 用五套基准（AIME OTIS Mock、Chess Puzzles、FrontierMath tiers 1–3、GPQA Diamond、Mystery Game Puzzles）构建成本与性能的 Pareto 前沿，测的是「达到某一能力水平所需的最低成本」，而不是每 token 单价。结论：2023 年以来，同等能力的价格平均每季度下降约 47%，折合每年降到约 1/13，比 DNA 测序快 4 倍、比算力快 6 倍、比锂电池快 18 倍、比 1892–1973 年的电力快 54 倍。单个例子：在 GPQA Diamond 上达到 75% 的水平，2025 年 1 月发布的 o3 约 $0.30/题，不到 18 个月后的 GPT-5.6 Luna 只要 $0.0004/题，降到约 1/725。

报告还发现降价速度与「离当时的 SOTA 有多远」有关：某个能力水平刚成为 SOTA 时平均每季度降 66%（年均 75 倍），两年后减半到 32%（年均 4.7 倍）。作者的解释是，新能力刚出现时厂商可以短暂收取溢价，被竞争者追平后价格迅速崩塌。方法上，他们把每个模型在不同推理档、不同 token 预算下的表现拼成成本-性能曲线（借 CAISI 的 transcript 预算模拟），再对前沿面拟合 Box-Tidwell 模型，并明确放弃了标准误与显著性检验，把结果定位为「合理但粗略」。

2. 我的解读

这份报告真正的价值不在「47%」这个数字，而在两点。其一，它把讨论从「每百万 token 多少钱」搬到「同一件事做完要多少钱」——推理模型可以多花 token，但能从更小、更便宜的底座模型里榨出同等表现，只看单价会得出相反的结论。其二，它给出降价的时间结构：靠近前沿的能力最贵、也跌得最快；已经稳定下来的能力，跌势明显放缓。这解释了常见的体感：半年没换模型，账单可能已经被同价位新模型在性价比上拉开了十几倍。

3. 对实际工程的意义

对做模型选型和成本控制的团队，这份报告支持三条做法：

  1. 把「按季度用同一批真实任务重新比价」变成固定动作。同等能力的价格年降约 13 倍，任何写死的成本假设都会很快过期。
  2. 评估要按任务总成本（含推理与重试 token）而不是单价，长链 agent 任务里缓存读取与输出 token 才是账单大头。
  3. 刚发布的前沿模型不要急着切生产流量——它正处在溢价期，竞争者通常几个季度就能把同等能力压到原来的零头。

4. 可信度与局限

方法与代码公开（GitHub 仓库 + 交互式页面），局限也列得清楚，可信度较高。主要保留：基准成绩可能被「benchmaxxing」注水（他们用游戏身份保密的基准做了对照，结果只比均值低几个百分点，说明问题存在但不致命）；基准成绩不等于有用工作；前沿假设了一个「永远在寻找最划算模型」的用户，真实团队不会这么频繁切换，实际节省小于报告值；三年数据偏短，作者自己也不报告标准误。还有一个技术细节值得知道：不同平均口径下总体季度降幅在 42.9%–58.0% 之间浮动，主结论对方法选择不算敏感，但 47% 不应被当成精确常数。

5. 最值得记住的三点

  • 同等能力的价格每年约降到 1/13，这个速度超过历史上任何一项通用技术。
  • 价格对「离 SOTA 多远」敏感：SOTA 当季 -66%，两年后 -32%，前沿溢价是暂时的。
  • 看任务总成本而不是 token 单价，否则会在推理模型上得出错误的选型结论。

我的推荐

值得完整读一遍，尤其是方法一节和 Limitations。如果只记一个可操作结论：把模型选型的复查周期定在季度级，按自己的真实任务重测总成本；报告里的数字可以作为量级参考，但不要直接当成自己的成本曲线。

展开完整精读

The Closed Quorum: Inside the first reported autonomous AI C2 implant

一句话判断：第一份公开、可验证地描述「把 C2 决策整体交给商用 LLM 面板」的 Windows 植入体分析。它不是更强的恶意软件，而是把攻击链的一环从人手上拿走（effort displacement），同时留下了一组可观测的关联行为特征。

1. 文章主张了什么

Cisco Talos 通过 CAIRN 项目拿到 CLOSEDQUORUM：一个 16.4MB、Go 编写、带未剥离 DWARF 符号的 64 位 Windows 可执行文件。它的核心设计是把 LLM 提供商当作 C2 基础设施：依次向 DeepSeek、Qwen、Mistral、Gemini 发结构化 prompt，汇总各家返回的 JSON 决策，用多数决选出动作，平票时按 DeepSeek > Qwen > Mistral > Gemini 的固定优先级裁决。模型被系统提示词约束成「advanced malware strategist，只输出可执行决策」，输出必须匹配固定 schema（decision: inject / persist / steal / move，外加 reasoning、target_process、exploit_type、evasion_method、payload_config），不匹配就丢弃。

动作路由到具体实现：steal 同时执行 LSASS 内存转储、浏览器凭据（Chrome/Edge/Firefox）与加密钱包（MetaMask、Exodus、以太坊）提取；inject 生成 shellcode 后走 Early Bird APC 或 process hollowing；persist 使用注册表 Run 键（伪装成 WindowsUpdate）、schtasks 与 WMI 事件订阅（落盘 wmi.ps1）。窃取物用按当天日期派生的密钥做 AES-256-GCM 加密、base64 编码后按 1900 字节分片、每秒一片发到操作者的 Discord webhook；同时用 ETW 补丁（把 EtwEventWrite 覆盖成 RET）、5 分钟启动延迟与 5–15 分钟随机轮询规避沙箱。公开分发的那份二进制是空模板（dummy key、dummy webhook），Talos 判断这是按操作者定制编译的「凭据窃取即服务」，尚未确认野外部署。

2. 我的解读

把 C2 服务器换成四个商用 API，好处不是隐蔽而是不可归属与低成本：没有域名、没有 IP、没有证书透明度日志可以提前发现，被一个模型拒绝还有另外三个，操作者可以下线睡觉，植入体自己每 5–15 分钟作一次决策。Talos 也点破了这套设计的弱点：依赖商用 API 就意味着依赖对方的拒绝、限流和返回格式，schema 一旦不被满足，整个循环就退化成 sleep-retry；写死的平票优先级也让行为可预测。

3. 对实际工程的意义

对防御方结论很具体：不要按域名封（合法应用每天都在连这些 API 和 Discord），要看关联行为——某个无法解释的 Windows 进程同时在向多个模型提供商发请求、访问 LSASS、注入挂起进程、写 WMI 持久化、再往 Discord 外发，这种组合才是信号。对做 agent 的人，这篇也是一个提醒：agent 的 API 凭据、上下文和本地数据本身就是被收割的资产（当天另一条 infostealer 研究也在说同一件事），密钥最小化与轮换、收紧敏感进程的访问权限都是可执行的动作。

4. 可信度与局限

这是静态分析（附 YARA 规则与 7 天开发链的 SHA256），不是野外流量捕获：作者明确说明公开包是惰性模板、没有观察到端到端执行，给出的系统提示词与 schema 也可能在真实运营时被改动。文章里几段关键代码块（prompt 模板与 Go struct）在我的网页抽取结果里被剥离，能看到的是正文引用的字段与逻辑描述。另外「自主决策」的边界要说清楚：动作空间是预先写死的四类，模型做的是选择与参数填充，而不是自己发明攻击链路——作者自己也强调，把决策空间压缩成受限选项正是可行的前提。

5. 最值得记住的三点

  • 「LLM 即 C2」：用多家模型多数决加固定平票优先级替代传统 C2 服务器，操作者可以离线。
  • 把攻击决策编码成受限 JSON schema，是从模型输出到真实执行的关键一步，也是防御方可以卡住的接口。
  • 检测靠行为组合（多模型 egress + LSASS/注入/持久化 + Discord），单点域名封锁无效。

我的推荐

想理解「AI 驱动的攻击自动化」现在走到哪一步，这篇是目前最好的公开样本；防御团队值得把文末的行为特征表当成一条现实的检测需求记录。对文中的日期密钥加密、ETW 补丁等细节，按常规逆向材料处理即可。

Claude Opus 5.5, GPT-6 Sol, GPT-6 Luna, and a new price war

1. 文章主张了什么

作者把当天的定价摆成一张表（每百万 token，输入/输出）：GPT-6 Luna $0.10/$0.50、GPT-5.6 Luna $0.20/$1.20、Grok 4.7 $2/$6、GPT-6 Sol $2/$10、GPT-5.6 Terra $2/$12、Claude Opus 5.5 $4/$20、GPT-5.6 Sol $4/$20、Claude Fable 5.1 $10/$50、GPT-6 Astra $10/$50。两个关键事实：其一，GPT-6 Sol/Luna 的价格是 GPT-5.6 对应档位的一半，而 GPT-5.6 在 11 月还有一次 25% 的涨价，所以这个「一半」比的是促销价；其二，Opus 5.5 把输入/输出从 $5/$25 降到 $4/$20（-20%），缓存读取从 $0.50 降到 $0.20（-60%），作者特别指出这对缓存命中占九成以上的长 agent 会话影响最大。

负面观察同样具体：Opus 5.5 在「max」推理档两次都在画 SVG 的例子中耗尽了 12.8 万输出 token 上限、根本没有返回结果，单次约 $2.56、耗时近 20 分钟；作者据此判断 max 档「实际上不可用」。他本人已经把 Codex 与 Claude Code 的默认模型换成 GPT-6 Sol 和 Opus 5.5，并把 Datasette Agent 的演示切到 GPT-6 Luna。

2. 我的解读

这条最值得看的不是排行榜，而是两件工程事实。第一，降价主要落在缓存输入与次一级模型上，对长上下文、多轮 agent 类负载的实际降幅大于名义单价降幅。第二，新模型在高推理档上的行为不确定性，可能以「烧满输出预算然后失败」的方式结算，而不是以错误答案结算——后者对成本控制更危险：它既不产出结果，也不报错，只是把账单做大。

3. 对实际工程的意义

可直接落地的三条：

  1. 把「max/最高推理档」当成需要显式预算上限的档位，而不是默认档——至少在最容易触发长篇推理的任务上加输出 token 上限和超时熔断。
  2. 评估迁移收益时按缓存命中的实际比例折算：长会话负载里缓存读取降 60% 往往比单价降 20% 更值钱。
  3. 价格战的节奏是季度级而非年度级，选型复查也应按这个节奏；同时注意 GPT-5.6 十一月涨价这类时间点会让当前的对比失真。

4. 可信度与局限

作者是一线独立工程作者、长期跟踪模型价格与实测行为，价格表、失败时的花费与耗时都能回溯到公开页面；但整体是个人印象式笔记而非系统评测，画 SVG 的测试也不代表真实工作负载——他自己也承认用画鹈鹕比较不同厂商「可能本来就没什么意义」。价格表的时效性以天计，用之前要回看官方价目页。

5. 最值得记住的三点

  • GPT-6 Sol/Luna 把同档价格砍半、Opus 5.5 缓存读取降 60%：长 agent 会话的省幅大于名义单价降幅。
  • Opus 5.5 的 max 档可能出现「耗尽输出上限、不返回结果」的失败模式，而且照价计费。
  • 价格战的节奏是季度级而非年度级，选型复查也应按这个节奏来。

我的推荐

花六分钟读完值得，尤其是价格表和 max 档失败那一段。采用它的结论时请自己核价：这张表是当天的快照，而对手方还有一次计划中的涨价。

Keeping Large MoE Training Within Fixed GPU Memory (20 minute read)

Four are left unbounded by the parallelism plans in common use, and each grows differently: expert dispatch with the routing matrix, the vocabulary projection with tokens times vocabulary, gradient checkpoint boundaries with depth times sequence length, and optimizer state with parameter count. Which one runs out first changes with the model, the context length, and the device count, so lowering the largest only exposes the next. We bound all four with schedules whose GPU working set is fixed at launch: PipelinedLLEP extends least-loaded expert parallelism with a cap on the tokens each source contributes to a dispatch chunk, Ring-DTP circulates activations or weight shards around a ring at the vocabulary projection and folds each block of logits into an online log-sum-exp, Selective checkpoint offload (SCO) keeps the one long-lived tensor of each checkpoint boundary in CPU memory, and OffloadStreamAdamW turns the serial CPU Adam update of optimizer offload into a bucket pipeline. All four change only the order and granularity of computation and data movement, so the loss and gradients stay exact. In matched component tests, they cut the MoE dispatch peak by up to 59.3% without losing throughput, the vocabulary projection peak by 86.6%, and the offloaded optimizer step by 2.05× faster.
